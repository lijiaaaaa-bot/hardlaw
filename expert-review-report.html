跨专家共识：P0 致命缺陷

以下问题被两位及以上专家独立发现并交叉验证，按风险排序。

  • 384/512 维向量不匹配 → iOS 语义检索恒为空
    文档向量 384 维（MiniLM），查询端 512 维（BGE），guard queryVec.count == dim 恒真触发，RRF 融合从未执行。混合搜索名存实亡。
    AI系统iOS架构 LawIndex.swift:236 CoreMLEmbeddingProvider.swift:21
  • Verdict blocking 字段 Swift/Python 静默数据损坏
    Swift toDict 输出字符串 kind，Python to_dict 输出布尔值。跨语言交换时：Swift 解码布尔抛 DecodingError，Python 解码布尔被归一化为 "none"——blocking 信息静默丢失。两处 "mirrors Python" 注释失实。
    iOS架构 Verdict.swift:71 verdict.py:123-124
  • Python _invoke_judge 无异常捕获 → 非 fail-closed
    LLM 抛错直接炸穿 hear()。Swift 端 fail-closed 为 blocking 裁决，Python 端不成立——双端行为分裂。注释声称的 "never throws" 在 Python 端不成立。
    AI系统 court.py:238
  • 验证失败但不 reject 的裁决可放行（假通过）
    Court.swift:246-254 仅在 defaultToReject==true 时强制 refuted；而工资标准核实等 statute 的 defaultToReject 为 false——幻觉引文 + 默认放行 = 虚假批准。
    AI系统 Court.swift:246-254 LaborLawStatutes.swift:52,87,99
  • 仲裁时效（调解仲裁法第27条）完全缺失
    法条库无时效 statute。郭案欠薪自 2023年12月起，解除后一年内（2027年5月8日前）必须申请仲裁——工具在证据链审查中完全不含时效要件。沉默失败，比可见错误更危险。
    劳动法 LaborLawStatutes.swift
  • "行政处罚事先告知书"与"行政责令决定"概念混淆
    additionalCompensation 要求的是第85条规定的"劳动行政部门责令限期支付"之责令决定，而非处罚程序的事先告知文书。以告知书充当责令证据，法律要件认定错误。
    劳动法 LaborLawStatutes.swift:94
  • 郭案 CODE 测试硬编码工龄 5 年，实际应为 5年10月 → 6 个月
    依第47条，参保 2020-07-01 至解除 2026-05-08 = 5年10个月余 → 6 个月补偿。硬编码 5 年低估 1 个月（7,550元），且测试只断言"跑通"不断言金额。
    劳动法 GuoYouyiCaseTests.swift:88-91
  • addFact 意图返回"已记录"但零写入 —— 假功能
    用户被引导输入案情描述 → 命中 addFact → 系统回复"已记录"→ 零写入。且 computeSeverance 失败引导的句式恰好触发此空操作。信任炸弹。
    产品 IntentParser.swift:204-209 CourtViewModel.swift:208-211
  • 引用验证声称"逐字核对原文"实际只查数字包含
    verifySnippets 仅做 numbers 子集检查。无源文件时静默通过（allMatch 保持 true），制造虚假安全感。UI 信任横幅"引用内容必须与原文逐字一致"承诺远超实现。
    产品 CourtViewModel.swift:325-339

专家追问精华

追问主题专家结论
最先修哪个法律问题？ 仲裁时效——杀伤范围最大（可杀死整案）、失败模式最隐蔽（无声失败）、修复杠杆最高（新增一部 statute 即可，不碰引擎逻辑）
Verdict blocking 统一为哪种格式？ 统一为字符串 kind，改 Python to_dict 两行、零测试破坏。字符串已是全仓事实标准（LLM 契约 + 两端解析器 + 9 处测试 mock）
LawStore 加锁 vs 不可变化？ 改为全部 let + throwing init——零成本（~100ns vs 100ms+ 分词）、删掉 @unchecked Sendable、编译器可验证
如何区分真实引用与 prompt 复读？ 三层反幻觉 v2：锚点解析引用（LLM 输出指针而非文本）+ 数字蕴含校验（确定性免费）+ 独立盲审交叉验证
findCommonGaps 能替代 LLM 吗？ 是地板不是天花板——激活作为 fallback 兜底（免费且正确方向），但不能替代 LLM。需加内容回退搜索、去重、严重度分级、接入 executeGoalStep
混同用工必须援引公司法吗？ 推荐双轨主张：劳动法路径（用工事实认定）主攻 + 公司法第23条第2款作规范锚点。对郭案，以用工混同为主更稳妥
