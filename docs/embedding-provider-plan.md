# EmbeddingProvider Implementation Plan

## Current State

### What exists today

| Layer | Detail |
|-------|--------|
| **Protocol** | `EmbeddingProvider` in `ios/HardlawKit/Sources/LegalKnowledge/EmbeddingProvider.swift` — 2 methods: `dimension: Int` and `embed(_ text: String) async throws -> [Float]` |
| **Consumer** | `LawIndex` in `ios/HardlawKit/Sources/LegalKnowledge/LawIndex.swift` — loads pre-computed 512-dim document vectors from `laws_vectors.bin`, uses provider to embed queries, merges via RRF |
| **Python model** | `BAAI/bge-small-zh-v1.5` (512-dim, SentenceTransformers) — Chinese-native, replaces MiniLM |
| **Vector data** | 11,724 pre-computed vectors at 512 dimensions, stored as float32 binary in `ios/HardlawApp/LegalKnowledge/laws_vectors.bin` (single copy; Kit/Resources copy removed in `cba13d4`) |
| **MLX infra** | `MLXLLM.swift` exists as a stub (all code behind `#if false`). `project.yml` depends on `mlx-community/mlx-libraries` package |
| **No provider** | No concrete `EmbeddingProvider` implementation exists — `LawIndex.search()` falls back to keyword-only |

### Core insight

The pre-computed document vectors are generated by Python (`scripts/export_for_ios.py`) and bundled as a resource. Changing the embedding model means **re-running the export script** to regenerate vectors in the new model's embedding space. This is an offline batch operation — a one-time cost.

The LawIndex reads dimension dynamically from the binary header (`laws_vectors.bin`), so switching to a model with a different output dimension (e.g., 512 instead of 384) requires no code changes in LawIndex — only re-export with the new model.

## Approach Comparison: CoreML vs MLX

### Option A: CoreML

**Architecture:**
```
Query text → swift-transformers (WordPiece tokenizer) → CoreML model → [Float] embedding → L2 normalize
```

**Dependencies:**
- `coremltools` (Python, build-time only) — convert PyTorch model to `.mlpackage`
- `huggingface/swift-transformers` (Swift Package) — BERT/WordPiece tokenizer at runtime
- `vocab.txt` file bundled as app resource

**Pros:**
- Zero runtime framework dependencies beyond iOS itself
- Apple Neural Engine (ANE) acceleration — best energy efficiency for repeated query embedding
- Model compiled at build time, deterministic
- Proven path: many sentence-transformers models successfully converted to CoreML
- `swift-transformers` package handles Chinese characters correctly (CJK Unicode range detection in BasicTokenizer)
- CoreML `.mlpackage` is typically 30-50% smaller than source weights due to compression
- No model download at runtime — everything in the app bundle

**Cons:**
- Separate tokenizer dependency (`swift-transformers`) adds complexity
- Conversion pipeline is a build step (Python script with `coremltools`)
- Tokenizer `vocab.txt` must be bundled separately from the model
- Model cannot be swapped at runtime (without bundling multiple models)
- `coremltools` conversion can be finicky — requires careful handling of `input_ids`, `attention_mask` shapes and the pooling layer
- Input shape flexibility (variable-length text) requires `ct.RangeDim` or `ct.EnumeratedShapes`

### Option B: MLX

**Architecture:**
```
Query text → MLXEmbedders (tokenizer + model) → [Float] embedding → L2 normalize
```

**Dependencies:**
- `mzbac/mlx.embeddings` (Swift Package) — embedding-specific MLX wrapper
  - URL: https://github.com/mzbac/mlx.embeddings
  - OR `MLXEmbedders` from `mlx-swift-examples` (official but larger dependency tree)
- `mlx-lm` (Python, build-time) — convert model to MLX format

**Pros:**
- Tokenizer bundled with model — single artifact to manage
- Aligns with existing MLX intent in the project (MLXLLM.swift)
- Can load different models at runtime (useful for A/B testing)
- Growing ecosystem, active community
- Model loading API is familiar (matches MLXLLM patterns)

**Cons:**
- `mzbac/mlx.embeddings` is a community package (not official Apple), version 0.1.0
- GPU-only (no ANE acceleration) — higher energy consumption
- MLX runtime adds memory overhead (~50-100 MB for the framework itself)
- First query is slow (model loading is lazy/async)
- **`bge-small-zh-v1.5` is NOT available in MLX format on HuggingFace** — must convert manually using `mlx-lm convert`
- The existing `project.yml` dependency (`mlx-community/mlx-libraries`) does **not** provide embedding support (only MLXMNIST and StableDiffusion). The project would need to add a separate package for embeddings regardless.
- Larger app binary due to MLX framework

### Quick Comparison Table

| Factor | CoreML | MLX |
|--------|--------|-----|
| **Extra Swift dependencies** | 1 (`swift-transformers`) | 1 (`mlx.embeddings` or `MLXEmbedders`) |
| **Runtime framework overhead** | None (built into iOS) | MLX runtime (~50-100 MB RAM) |
| **Hardware acceleration** | ANE + GPU + CPU | GPU only |
| **Energy efficiency** | Excellent (ANE) | Good (GPU) |
| **Tokenizer handling** | Separate (`swift-transformers` + `vocab.txt`) | Bundled with model |
| **Model conversion** | `coremltools` (Python) | `mlx-lm convert` (Python) |
| **Pre-converted bge-small-zh available?** | No (manual conversion needed) | No (manual conversion needed) |
| **Model size on disk** | ~100-150 MB (CoreML compressed) | ~91 MB (BF16) or ~45 MB (8-bit) |
| **Build-time complexity** | Medium (Python conversion script) | Low (just download safetensors) |
| **Runtime complexity** | Medium (separate tokenizer + CoreML inference) | Low (single `loadModelContainer` call) |
| **API familiarity** | New (CoreML API) | Familiar (matches MLXLLM pattern) |
| **Supported architectures** | Any PyTorch model → CoreML | BERT, RoBERTa, XLM-RoBERTa, DistilBERT, Qwen2/3 |
| **iOS minimum** | iOS 17.0 (matches project) | macOS/iOS 14.0+ |

## Tokenization Deep Dive

### The problem

BERT-family models (including bge-small-zh-v1.5) use **WordPiece subword tokenization** with a fixed vocabulary. The tokenizer must match the model's `vocab.txt` exactly. This is fundamentally different from:
- iOS `NLTokenizer` — linguistic word segmentation, NOT subword tokenization
- Character-level tokenization — too coarse, loses semantic information
- Whitespace splitting — doesn't work for Chinese

### CoreML tokenization solution: `huggingface/swift-transformers`

**Package URL:** https://github.com/huggingface/swift-transformers

This is the official HuggingFace Swift package for tokenization. It includes `BertTokenizer` implementing the full WordPiece algorithm with Chinese character handling.

**How it handles Chinese:**
1. `BasicTokenizer` adds spaces around CJK Unicode characters (range U+4E00–U+9FFF, etc.)
2. `WordpieceTokenizer` then applies greedy longest-match-first on each whitespace-delimited token
3. Chinese characters become individual tokens (each character is a separate word after BasicTokenizer), UNLESS multi-character words exist in the vocabulary

**Usage pattern:**
```swift
import Tokenizers

// Load tokenizer from bundled files
let tokenizer = try await AutoTokenizer.from(
    modelPath: Bundle.main.url(forResource: "bge-small-zh-v1.5", withExtension: nil)!
)

// Tokenize
let encoded = tokenizer.encode(text: "劳动合同解除需要什么条件")
// encoded.inputIds → [Int32] padded/truncated to maxLength
// encoded.attentionMask → [Int32]
```

**Files needed in the app bundle:**
- `vocab.txt` (107 KB, 21,128 tokens)
- `tokenizer_config.json` (367 bytes)

**Installation in project.yml:**
```yaml
packages:
  swift-transformers:
    url: https://github.com/huggingface/swift-transformers
    from: "1.1.6"
```

### MLX tokenization: handled by model loading

With `mzbac/mlx.embeddings`, the tokenizer is loaded automatically as part of the model container:
```swift
let container = try await loadModelContainer(
    configuration: ModelConfiguration(id: "BAAI/bge-small-zh-v1.5")
)
// Tokenizer is available inside container.perform { model, tokenizer in ... }
```

No separate tokenizer files or package needed. The model weights and tokenizer are downloaded together.

## Detailed Conversion Steps

### CoreML Path

**Step 1: Python conversion script**

Create `scripts/convert_bge_to_coreml.py`:

```python
"""
Convert BAAI/bge-small-zh-v1.5 to CoreML for iOS embedding.
"""
import coremltools as ct
import torch
import torch.nn as nn
from sentence_transformers import SentenceTransformer
import numpy as np

MODEL_ID = "BAAI/bge-small-zh-v1.5"
OUTPUT_PATH = "ios/HardlawApp/bge-small-zh-v1.5.mlpackage"
MAX_SEQ_LEN = 512

def main():
    # Load the sentence-transformers model
    st_model = SentenceTransformer(MODEL_ID)
    
    # Get the underlying transformer + pooling
    # bge-small-zh-v1.5 uses mean pooling with attention mask
    transformer = st_model._first_module()
    pooling = st_model._last_module()  # Pooling layer
    
    # Wrap for tracing: input_ids + attention_mask → pooled embedding
    class EmbeddingWrapper(nn.Module):
        def __init__(self, transformer, pooling):
            super().__init__()
            self.transformer = transformer
            self.pooling = pooling
        
        def forward(self, input_ids, attention_mask):
            # Run transformer
            outputs = self.transformer.forward({
                'input_ids': input_ids,
                'attention_mask': attention_mask
            })
            # Apply pooling (mean pooling with attention mask)
            features = self.pooling.forward({
                'token_embeddings': outputs['token_embeddings'],
                'attention_mask': attention_mask
            })
            # Return sentence embedding
            return features['sentence_embedding']
    
    wrapped = EmbeddingWrapper(transformer, pooling)
    wrapped.eval()
    
    # Trace with dummy inputs
    dummy_ids = torch.zeros((1, MAX_SEQ_LEN), dtype=torch.long)
    dummy_mask = torch.zeros((1, MAX_SEQ_LEN), dtype=torch.long)
    
    traced = torch.jit.trace(wrapped, (dummy_ids, dummy_mask))
    
    # Convert to CoreML
    mlmodel = ct.convert(
        traced,
        inputs=[
            ct.TensorType(name="input_ids", shape=(1, ct.RangeDim(1, MAX_SEQ_LEN))),
            ct.TensorType(name="attention_mask", shape=(1, ct.RangeDim(1, MAX_SEQ_LEN))),
        ],
        outputs=[
            ct.TensorType(name="sentence_embedding")
        ],
        minimum_deployment_target=ct.target.iOS17,
        compute_precision=ct.precision.FLOAT16,
    )
    
    # Add model metadata
    mlmodel.short_description = "BGE-small-zh-v1.5 embedding model for Chinese legal text"
    mlmodel.version = "1.5"
    
    mlmodel.save(OUTPUT_PATH)
    print(f"Saved CoreML model to {OUTPUT_PATH}")

if __name__ == "__main__":
    main()
```

**Step 3: Swift implementation**

```swift
import CoreML
import Tokenizers  // swift-transformers

actor CoreMLEmbeddingProvider: EmbeddingProvider {
    let dimension = 512  // bge-small-zh-v1.5 output dim
    
    private let model: MLModel
    private let tokenizer: Tokenizer  // from swift-transformers
    
    init() throws {
        // Load compiled CoreML model
        guard let modelURL = Bundle.main.url(
            forResource: "bge-small-zh-v1.5", withExtension: "mlmodelc"
        ) else {
            throw EmbeddingError.modelNotFound
        }
        self.model = try MLModel(contentsOf: modelURL)
        
        // Load tokenizer
        guard let tokenizerURL = Bundle.main.url(
            forResource: "bge-small-zh-v1.5-tokenizer", withExtension: nil
        ) else {
            throw EmbeddingError.tokenizerNotFound
        }
        self.tokenizer = try await AutoTokenizer.from(modelPath: tokenizerURL)
    }
    
    func embed(_ text: String) async throws -> [Float] {
        // Tokenize
        let encoded = tokenizer.encode(text: text)
        
        // Create MLMultiArray inputs
        let inputIds = try MLMultiArray(encoded.inputIds)
        let attentionMask = try MLMultiArray(encoded.attentionMask)
        
        // Run inference
        let input = MLDictionaryFeatureProvider(dictionary: [
            "input_ids": inputIds,
            "attention_mask": attentionMask
        ])
        let output = try await model.prediction(from: input)
        
        // Extract embedding and L2-normalize
        guard let embedding = output.featureValue(for: "sentence_embedding")?.multiArrayValue else {
            throw EmbeddingError.invalidOutput
        }
        
        var vector = [Float](repeating: 0, count: dimension)
        for i in 0..<dimension {
            vector[i] = embedding[i].floatValue
        }
        
        // L2 normalize
        return l2Normalize(vector)
    }
}
```

**Gotcha: Mean pooling vs CLS token.** bge-small-zh-v1.5 uses mean pooling over all token embeddings (weighted by attention mask), NOT just the [CLS] token. The Python conversion script must trace through the full pooling layer. Using only `last_hidden_state[:, 0, :]` (CLS token) will produce wrong embeddings.

**Gotcha: Input shape flexibility.** CoreML models are compiled with fixed or flexible shapes. For query embedding, we need variable-length input (1 token to 512 tokens). Use `ct.RangeDim(1, 512)` in the conversion script. Fixed-shape models will fail on short queries.

**Step 3: Swift implementation**

```swift
import MLXEmbeddings

actor MLXEmbeddingProvider: EmbeddingProvider {
    let dimension = 512
    
    private var modelContainer: ModelContainer?
    private var isLoaded = false
    
    // HuggingFace model ID (use local path or HF repo)
    private let modelId = "BAAI/bge-small-zh-v1.5"
    
    func loadIfNeeded() async throws {
        guard !isLoaded else { return }
        let config = ModelConfiguration.configuration(id: modelId)
        modelContainer = try await loadModelContainer(configuration: config)
        isLoaded = true
    }
    
    func embed(_ text: String) async throws -> [Float] {
        try await loadIfNeeded()
        
        guard let container = modelContainer else {
            throw EmbeddingError.modelNotLoaded
        }
        
        return try await container.perform { model, tokenizer in
            let tokens = tokenizer.encode(text: text)
            let input = MLXArray(tokens).expandedDimensions(axis: 0)
            
            // Forward pass through the model
            let output = model(input)
            
            // Mean pooling (bge-small-zh uses mean pooling)
            let embeddings = output.lastHiddenState.mean(axis: 1)
            
            // L2 normalize
            let norm = embeddings.square().sum().sqrt()
            let normalized = embeddings / norm
            
            // Convert to Swift [Float]
            return normalized.asArray(Float.self)
        }
    }
}
```

## Recommendation

### Primary recommendation: CoreML + bge-small-zh-v1.5

**Why CoreML over MLX for this specific use case:**

1. **Embeddings are a BATCH operation for documents, but a SINGLE-QUERY operation at runtime.** The heavy lifting (embedding 11,157 legal chunks) is done offline in Python. At runtime on iOS, the model only embeds a single query string (~20-100 characters). This is the ideal workload for CoreML's ANE: small, frequent inference with minimal energy cost.

2. **The MLX infrastructure isn't ready yet.** `MLXLLM.swift` is entirely behind `#if false` — the real MLX integration is not wired up. Adding CoreML for embeddings is a working v1 that can ship independently of the MLX LLM work.

3. **Energy matters for a reference app.** Users consult legal references repeatedly. The ANE uses significantly less power than the GPU for the small inference workload of query embedding.

4. **Simpler debugging.** CoreML models are compiled at build time. There's no async download, no network dependency, no model version mismatch. If the app works on the developer's device, it works on all devices.

5. **`swift-transformers` is well-maintained.** It's the official HuggingFace Swift package, recently updated, with explicit Chinese character support in its BERT tokenizer.

### When to use MLX instead

Choose MLX if:
- You want to share the MLX runtime between embedding and LLM inference (reduced total memory footprint when both are active)
- You need to dynamically switch between embedding models at runtime
- The MLX LLM integration is already working and you want architectural consistency
- You prefer to download models post-install rather than bundle them

## Key Gotchas

1. **Pooling layer matters.** bge-small-zh-v1.5 uses mean pooling weighted by attention mask. If the CoreML conversion only grabs `last_hidden_state[:, 0]` (CLS token), embeddings will be wrong. The conversion script must trace through the full pooling module from sentence-transformers.

2. **Input shape flexibility.** CoreML models need `ct.RangeDim` or `ct.EnumeratedShapes` for variable-length input. Fixed-shape models will crash on short queries or require padding to exactly 512 tokens.

3. **L2 normalization.** The Python SentenceTransformer normalizes embeddings by default (`normalize_embeddings=True`). The iOS provider must do the same. The `EmbeddingProvider` protocol contract explicitly requires L2-normalized vectors.

4. **`vocab.txt` must match exactly.** The tokenizer vocabulary MUST be the same file used during model training. Copy it directly from the HuggingFace model repo — do not use a generic BERT Chinese vocab.

5. **CoreML compilation at build time.** The `.mlpackage` is compiled to `.mlmodelc` by Xcode at build time. The Swift code should load the `.mlmodelc` extension, not `.mlpackage`. If the model fails to load, check that it's included in the target's "Copy Bundle Resources" build phase.

6. **First-run latency (MLX only).** MLX models load lazily on first use. The first query will be slow (1-3 seconds for model loading). Subsequent queries are fast. Consider pre-warming during app launch.

7. **`bge-small-zh-v1.5` instruction prefix.** The BGE v1.5 model may benefit from an instruction prefix on queries: `"为这个句子生成表示以用于检索相关文章："` (Generate representation for this sentence to retrieve relevant articles). Test with and without this prefix against the document vectors.

8. **Dimension mismatch detection.** The `LawIndex` should validate that the provider's `dimension` matches the loaded vector dimension, and refuse to run semantic search with a clear error if they differ.
