# LLM 三层路由设计(隐私分层)

## 背景

模型选型 bench(2026-08-13,`scripts/bench_judge.py`,42 例评测集)实测:

| 模型 | 法条引用 | 数字蕴含 | 分类 | 平均 |
|---|---|---|---|---|
| deepseek-v4-flash(云端) | 15/15 | 6/8 | 14/15 | 89.4% |
| Qwen2.5-3B-4bit(本机) | 15/15 | 5/8 | 13/15 | 83.1% |
| Qwen2.5-0.5B-4bit(本机) | 12/19 | 5/8 | 8/15 | 59.7% |

> ⚠️ 扩充后(17→42 例)实测:云端与本地 3B 真实差距 6.3%(非旧评测的 1.4%)。
> 三者法条引用均强(3B/flash 100%),差距在**数字派生计算**(2N 封顶/2.5 个月)
> 与**边界分类**。0.5B 显著不足(59.7%,分类 53.3%,派生计算错误)——iOS 默认
> 回退用 0.5B 仅能兜底,不能作为主模型。扩充前 94.4% 是熟悉用例的假象,
> 模型选型以扩充后为准。

iPhone 16 Pro Max(8GB):0.5B 可用、3B 勉强、35B-A3B(38GB)不可行。

律师合规评估(见 intent-lab artifact `0a45a68eba8f40ae`):
原始证据(身份证/银行流水/聊天记录)属敏感个人信息,发第三方 API 违反
《个人信息保护法》第39/55条(单独同意+PIA),破坏律师保密特权,云端黑盒不可审计。

## 三层路由(已实现 + 设计边界)

### 层 1:本地确定性引擎(默认,始终可用)
- `RuleBasedLLM` + `CompensationCalculator` + `DocumentClassifier` + 数字蕴含验证
- 全部本地、可追责、确定性;覆盖大部分自动化场景(缺口检测/分类/计算)
- **代码位置**:`CourtViewModel.llm` 的 fallback 分支

### 层 2:本地 MLX(离线增强)
- `MLXLLM`(Qwen2.5-3B-4bit,pinned revision 4f83f8f)→ `FailSafeLLM` 兜底
- 数据不出设备;`MLXLLM.isAvailable` 检查缓存,未缓存自动降级
- **代码位置**:`CourtViewModel.llm` 的 primary 分支(`if MLXLLM.isAvailable`)
- 注意:`defaultModelID` 已从 0.5B 提升到 3B(此前 P1-2 落地);模拟器恒 false(MLX 硬崩溃)

### 层 3:云端(可选项,未实现——需满足前置条件)
- deepseek-v4-flash 实测 95.8%,但**不能直接接入**
- **前置条件(律师要求,全部满足才可启用)**:
  1. [ ] 字段级 PII 脱敏模块(身份证/银行卡/手机号/人名 → 占位符)后再发送
  2. [ ] 用户单独同意弹窗(PIPL 第39条)
  3. [ ] 隐私政策 + 数据处理协议(DPA)
  4. [ ] PIA 记录存档
- **架构建议**:接入时复用 `FailSafeLLM(primary: CloudLLM, fallback: MLXLLM...)`,
  保持"云端失败 → 本地 3B → 规则引擎"的降级链

## 路由判定(建议)

```
默认 → 层 1(确定性,零延迟)
需要 LLM 裁决:
  ├─ 模型已缓存 && 用户偏好本地 → 层 2(MLX 3B)
  ├─ 层 3 已启用 && 用户同意脱敏 → 层 3(云端 flash,失败回落层 2)
  └─ 否则 → 层 2(MLX)或层 1(规则)
```

## 现状总结

- 层 1 + 层 2 **已实现**(CourtViewModel.llm)
- 层 3 **未实现**,保持"绝不联网"现状(合规正确)
- 如需云端能力,先做 PII 脱敏模块(合规前置,也是独立技术资产)
